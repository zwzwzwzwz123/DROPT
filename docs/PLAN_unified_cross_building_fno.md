## 0. 一句话

现在是**每栋楼单独训一个模型**（三栋三个）。本方案 = **训一个维度无关的 FNO，跨三栋不同 zone 数（6/18/25）的楼通用**，并用**零样本迁移**（训过的楼 → 没见过的楼）产出"MLP 物理上做不到、FNO 能"这张杀手图。

## 1. 为什么值得做（价值论证）

1. **兑现论文已吹的牛**：FNO 的理论卖点是"离散无关 / 跨规模"。但现在每栋楼配一个专属模型 = 嘴上通用、手上专用，自打脸。**训一个模型跨三栋楼，才是把这个主张真正演示出来。** 现在这块是空的。
2. **最锋利的"为什么是 FNO"实验**：两栋楼训一个 FNO → 零样本丢给没训过的第三栋。
   - FNO（算子形式，维度无关）**能跑**；
   - MLP 输入/输出维度写死，换 zone 数**连启动都不行**（不是性能差，是物理上跑不了）。
   - "MLP 连试的资格都没有，FNO 能迁移" = 分楼模型永远给不出的证据，是整个 FNO 故事的自然高潮。
3. **不撞车、是自己的地盘**：跨建筑可迁移的 HVAC 算子策略是领域特定新问题，无正面竞争。对比 OPD/MoE 都是 2026 热点赛道（重蹈 guidance 撞 QGPO/QGF 覆辙）。
4. **在 BEAR 里天然成立**（关键）：BEAR `action_dim == zone 数`（逐区设定点），所以"FNO 沿动作轴 = 沿空间轴 = 沿 zone 轴"，跨楼 = 跨轴长，FNO 的强项。⚠️ 这条**只在 BEAR 成立**——Sinergym 动作是 1-2 全局设定点、与 zone 无关，该方向在 sinergym 被否（`HANDOFF_sinergym_direction.md`）。**留在 BEAR 是这条路成立的前提。**

## 2. 代码现状核查（07-15 逐行核实，ground truth）

### 2.1 FNO 主体：已经维度无关（本来就成立，无需改）
`diffusion/model_fno.py`：
- `SpectralConv1d`（:16-49）：`rfft` 对任意轴长工作；`modes=min(self.modes, x_ft.shape[-1])`（:38）自动适配；权重 `[in_ch, out_ch, modes, 2]`（:29，末维 2=实/虚部）**不含轴长**。→ 6 区还是 25 区都能跑。
- `input_proj` `Conv1d(1, width, k=1)`（:94）、`pointwise` `Conv1d(width,width,k=1)`（:101）、`out_proj` 末层 `Conv1d(width,1,k=1)`（:109）：全是 kernel=1 卷积，**沿长度轴共享权重、任意长度通用**。
- **结论：FNO 的"沿 zone 轴"那条通路本来就与 zone 数无关。这是 FNO 理论卖点在代码里已然成立的地方。**

### 2.2 只有两处把维度焊死（要改的就这俩）
- **① `state_mlp` 首层 `Linear(state_dim, width)`**（:81）：吃 state 维 20/56/77，跨楼不同。
- **② `residual` `Linear(action_dim, action_dim)`**（:113）：吃动作维=zone 数 6/18/25，跨楼不同。

### 2.3 State 结构：天生适合 token 化（这条是"能干净改"的关键）
`BEAR/BEAR/Env/env_building.py:265-269`，state = `concatenate((X_new[roomnum], OutTemp[1], ghi_repeated[roomnum], GroundTemp[1], occ_repeated[roomnum]))`：
- **维度自洽核实**：roomnum + 1 + roomnum + 1 + roomnum = **3×roomnum + 2**，与 `building_env_wrapper.py:159` `state_dim = 3*roomnum + 2` 完全对上。✓ 这是"state 能干净拆成逐区+全局"的硬证据。
- **真正逐区不同的只有 `X_new`（每区温度）**。⚠️ `ghi_repeated`/`occ_repeated` 是**一个全局标量 `np.full` 复制 roomnum 遍**（:265-266）——即每区那份 ghi/occ **值完全相同**，不是真逐区量。OutTemp/GroundTemp 是纯全局标量各 1。
- → 干净的拆法：**全局量 = {OutTemp, GroundTemp, ghi, occ} 4 个标量**（ghi/occ 取一份即可，无需复制）；**逐区 token = 每区仅 {X_new_i} 1 个真特征**（或 {X_new_i + 广播的 4 全局量} 拼成每 token 5 维，看编码设计）。**这个"复制 N 遍"的写法本身就在提示可拆性**，但别被"3×roomnum"骗成"每区 3 个独立特征"——实际每区独立信息只有温度 1 个。**改成维度无关不是硬凑，是顺着数据本来的结构；但 token 特征怎么拼要基于这个真相设计。**

### 2.4 Critic 也吃维度（训练时用，别漏）
`diffusion/model.py:114-168` `DoubleCritic`：`state_mlp` `Linear(state_dim,hidden)`（:154）+ `q_net` `Linear(hidden+action_dim, ...)`（:163）焊死输入维；但**输出是标量 Q**（:167）——输出侧天生维度无关，只需处理输入侧。

## 3. 改法（两处焊死点 + critic + 训练流程）

### 3.1 actor 的 state_mlp（焊死点①）→ 逐区 token 编码
- 按 §2.3 真相拆：**全局量 4 标量 {OutTemp, GroundTemp, ghi, occ}** + **逐区 token（每区 {X_new_i} + 广播的 4 全局量 = 每 token 5 维）**。
- 逐区 token 用**共享逐 token MLP**（`Linear(5, width)`，对每区独立同权重）→ [B, roomnum, width] → 转置 [B, width, roomnum]，正好喂 FNO 的 zone 轴。
- **要点**：逐 token MLP 权重与 roomnum 无关（每区复用同一份），这才是维度无关的核心。⚠️ 实做前先 dump 一条真实 state 向量核对**精确索引顺序**（§2.3 只给了 concat 顺序，别拍脑袋切片）。

### 3.2 actor 的 residual（焊死点②）→ 逐区共享
- 现 `Linear(action_dim, action_dim)`（:113）把整条动作当整体映射、含跨区耦合、维度写死。
- 改成维度无关的**逐区残差**：最简 = `Conv1d(1,1,k=1)`（逐区共享标量仿射）。**代价**：丢原残差的"跨区线性混合"——但那本就该由 FNO 谱层承担，且阶段三 §10.5 已证残差非 essential（NoRes 近 Pareto），损失可控。
- ⚠️ 这一步让"统一模型"与"分楼主表模型"结构不完全可比（残差形式变了），报告须说明。

### 3.3 critic → 先"独立 critic + 统一 actor"探路
- **第一版建议**：**只让 actor 维度无关，critic 每栋楼各留一个独立的**（critic 只是训练信号、不需要跨楼共享，不改它工程量骤降）。
- **纯正统一版（第二步再说）**：critic 也 token 化——每区 {state_feat_i, action_i} → 共享编码 → 沿区 pool → 标量 Q（输出本就标量 §2.4）。
- **建议顺序**：先"独立 critic + 统一 actor"验证信号，成了再考虑统一 critic。

### 3.4 训练流程 → 多楼联合采样
- 现每 run 单楼。改成一个 collector 轮转/混合三栋 env，actor 参数共享、按楼路由 state/action 维度。
- 🔴 **最容易翻车的点 = reward/loss 尺度**：三栋能耗量纲差极大（871 vs 7016 vs 6418），不按楼归一化则**大楼主导梯度、小楼被淹**。温度/舒适度量纲三栋相近问题不大，但能耗项必须按楼归一化。这是工程上第一优先解决的。

## 4. 实验设计（先小后大、先筛信号、探针当闸门）

**Step 0（决策闸门，最省）· 零样本"能不能跑"探针**
- 拿现有单栋 FNO，做完 §3.1/§3.2 维度无关改造，用某栋权重**直接前向**到不同 zone 数的楼（**不训练**）。
- 只验证：改造后 FNO 在别的 zone 数上**跑得通、给得出形状正确的动作**；同时确认 MLP 在此维度**直接报错**（杀手图的反面）。
- **成本极低、是整条路的决策闸门**：跑不通→架构改法有问题，先修；跑通→继续。⚠️ "跑通"只说明维度无关成立，**不代表动作合理**（那要 Step 2 训练后才知道）。

**Step 1 · 统一 actor 联合训（管三栋，含独立 critic）**
- 三栋联合训一个 actor，对照三个分楼专家（现有主表）。看每栋掉幅。
- 判据：不掉/少掉→强（"1 个模型顶 3 个"）；掉一些→写成诚实 trade-off（"省 2/3 模型数、保留 X% 性能"）。**两种结局都能发。**

**Step 2 · 真零样本泛化（管两栋、留一栋完全不训）· 头条实验**
- 两栋训、第三栋完全 held-out，测统一模型在没见过的楼的性能。
- **杀手图**：FNO 能迁移（给出数字）、MLP 物理上跑不了（维度不匹配）。这是最强版本、也最可能不好看——**当加分项，不绑定发表**。

**优先级**：Step 0 立刻可做（判断成不成）；Step 1 是主体；Step 2 是天花板。
